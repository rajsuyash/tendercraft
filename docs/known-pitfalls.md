# Known pitfalls — read before writing code; append when you hit a new one

Format: **symptom → cause → fix.**

## Base

- Secrets in logs/commits → careless logging or hardcoding → env vars only; `.env` gitignored + deny-read in `.claude/settings.json`; grep before commit
- Double-submit creates duplicate tenders/proposals → no idempotency → disable-on-first-click + idempotency key on mutating endpoints
- N+1 on criteria/verdict lists (50+ rows per tender) → lazy per-row queries → batch/eager-load; one query per screen region
- List endpoints without pagination → unbounded growth (library hits 200+ docs fast) → default limit + cursor everywhere
- Time zones → naive datetimes → store UTC, convert at display; deadlines are IST-sensitive (submission 15:00 IST ≠ 15:00 UTC — a missed tender deadline is a lost bid)

## Web (Next.js)

- Hydration mismatch → `Date.now()`/locale strings in first render (deadline countdowns!) → render countdowns client-only or pass server timestamp props
- Hooks/handlers in a Server Component → missing `"use client"` → add at the leaf
- `NEXT_PUBLIC_` leaks → nothing sensitive in client-exposed vars (service-role key NEVER)
- Raw colors (`bg-white`, `#1F4E79` inline) → bypasses the design contract → semantic token classes only
- `next/image` without dimensions → layout shift on evidence/doc thumbnails → `width`+`height` or `fill`+sized parent
- UI built without opening its design_ref → generic screens that fail /design-review → open `design/reference/S<k>-*.png` + tokens first (seeded from the design handoff)

## Engine (FastAPI)

- `include_router` silently adds nothing (routes vanish, only inline `@app.get` survive) → fastapi 0.139+/starlette 1.3+ broke `include_router` (mounts routes as `path=None`). A stray `uv sync` upgraded into it. Fix: pin `fastapi>=0.115,<0.116` (pulls starlette 0.46). Symptom check: `[r.path for r in app.routes]` shows a `None`.

- Sync work in async handlers (OCR, PDF parse) → event-loop stall → background jobs; handlers stay I/O-thin
- Pydantic v1 syntax in v2 → `.dict()`/`validator` errors → v2 idioms (`model_dump`, `field_validator`)
- Forgotten `await` → coroutine never runs, silent no-op → ruff async lint rules on
- Mutable default args → shared state across requests → `None` + init inside
- Error responses leaking stack traces → default exception handler → global handler returns the envelope; traces to logs only
- Client-supplied tenant/user IDs trusted → authz bug class #1 and ET-6 Sev-1 → derive from validated JWT, always; integration test asserts body-supplied tenant_id is ignored
- Missing rate limits on public endpoints (upload!) → abuse/cost blowup → per-tenant rate limit at the edge

## AI pipeline

- Exact-text assertions on generative output → flaky forever → assert schema/fields/thresholds (golden sets)
- Editing a golden case to make a failing eval pass → eval fraud → thresholds change only via human PRD edit
- Prompt changed = behavior changed → any `prompts/` diff requires `/evals` before done
- Unbounded model retries → cost blowup → retry cap 1 + timeout in the one client module
- Model output used unvalidated → one malformed response crashes the pipeline → schema-validate → retry once → deterministic fallback (queue for human), never crash, never invent
- Verdict logic drifting into prompts → model "deciding" eligibility (PRD §2.4 violation) → comparators and gates live in `app/deterministic/` only; import check enforces
- Tender text treated as instructions → prompt injection from hostile documents (G-6) → allowlisted output schema; extractor has no tools; document content never parameterizes fetch/shell
- Financial figures generated by the Drafter → ET-3 critical → transclusion tokens only (B-FR3); citation validator + export gate catch, but don't rely on the gate — the Drafter prompt forbids numerals not present in retrieved chunks
- Confidence thresholds scattered as magic numbers → drift between UI and engine → single constants module, cited to PRD (0.80 extraction / 0.75 matcher)
- Drafter prompt tells the model to "cite the figure" for a financial criterion → `validate_citations` HARD-flags any `is_financial` sentence that isn't a transclusion **regardless of citation** (B-AC4) → the drafter must never author an amount at all: assert the bidder MEETS the requirement + cite the proving chunk, `is_financial:false`; real values transclude from structured data (B-FR3). Symptom: every financial criterion comes back `unverified`/placeholder.
- Whole content library fed to every criterion's drafter → the model is inconsistent about which doc supports which requirement (valid cert present but response placeholders) → per-criterion evidence selection (`pipeline/retrieval.py::select_evidence`): guarantee an attached doc's inclusion but keep relevance ordering so a noisy attachment can't bury the good cert

## Supabase

- RLS forgotten on a new table → silent cross-tenant reads → migration checklist: every table gets tenant_id + RLS policy + isolation test before merge
- Service-role key used in web code → RLS bypassed entirely → service-role only in the engine; web uses anon key + session
- pgvector similarity without tenant filter → ET-6 leak via retrieval → tenant filter BEFORE similarity ranking, tested in CI
- User-supplied URL fetched with string-only host check → SSRF to cloud metadata via DNS-rebind or 302→169.254.169.254 → resolve every hop with getaddrinfo, reject any private/loopback/link-local/reserved/multicast IP, follow redirects manually with re-validation, stream with a byte cap (`app/knowledge.py::fetch_url_text`)
- `follow_redirects=True` on any fetch of untrusted URLs → silently re-enables the redirect-to-metadata bypass → keep it False and re-validate each hop
- Upsert `on_conflict` target that omits `tenant_id` → a service-role merge (RLS bypassed) overwrites another tenant's row (its `tenant_id` gets reassigned) when the caller supplies a foreign conflict key → put `tenant_id` in the unique constraint AND the on_conflict list, and validate ownership in code before any write that binds a caller-supplied id (`db.get_criterion_in_tender` guards the readiness-decision + doc-link paths)
- Binding a caller-supplied `criterion_id`/`tender_id` to a row without checking it belongs to the caller's tenant+tender → ET-6 cross-tenant write → one existence query (`criteria?id=eq&tender_id=eq&tenant_id=eq`) gates it; the endpoint 404s before writing
- Model-supplied `is_financial` gating the "hard, non-overridable" B-AC4 financial gate → the prompt told the model to always send `false`, so the gate was unreachable and the only protection was prompt obedience (live eval drf-004 showed the model already breaking that prompt while passing with 0 flags) → derive `is_financial` from the sentence TEXT in `app/deterministic/drafting.py`; the model may only propose a class (`claim|narrative`) and `classify_sentence` coerces one-directionally toward CLAIM. Never let a model self-report the field that decides its own gate.
- Narrative/methodology prose flagged wholesale as `unverified` → cite-or-flag applied to forward commitments that have nothing to cite → `SectionKind.NARRATIVE` + a sentence class taxonomy. But tune the coercion on real output: a bare `certif` stem matched "Project Closure Certificate", and bare digits matched "Tier 1"/"Severity 3"/the tender reference number. Named credentials only; neutralise enumeration labels and reference numbers before the digit test; a digit inside a forward commitment ("the L3 team will…") is design detail, not an evidence claim. Money stays caught unconditionally.
- A narrative section returning `has_sufficient_context:false` and placeholdering to 0 words → the MODEL was deciding whether a section could bail, and self-vetoed on noisy retrieval despite drafting happily with no evidence at all → `needs_bidder_evidence` on the section spec; sections written from tender requirements + professional practice ignore the model's veto. An empty section scores zero.
- `select_evidence` returning whole documents that the drafter then truncates to 1200 chars → on a 20-page past proposal the model reads the cover page and nothing else → chunk to overlapping windows with ids `<doc_id>#<n>`. When you do, fix the pinned-doc lookup to compare DOCUMENT ids: pinned ids are `library_documents.id` but chunk ids carry `#n`, and comparing raw silently stops honouring "attach a doc to this criterion".
- A score that never reads the artifact it claims to score → `estimator.estimate()` took only a pre-drafting eligibility pass-rate, so regenerating the proposal could not move it → keep prediction (suppression-gated, D-AC4) and measurement (never suppressed) as separate functions; merging them either darkens the useful number or lets a prediction escape suppression.

## Multi-workspace tenancy (added with migrations 0009–0014)

- A profiles row alone grants NOTHING since 0011 → `current_workspace_id()` resolves the active workspace and then validates it against `workspace_members`; a fixture or admin path that writes only a profile silently produces a user who sees zero rows everywhere → always write both (test helper: `grant_membership`).
- `current_workspace_id()` returns a SCALAR on purpose → `apps/web` has no tenancy code; 24 server-component queries rely entirely on RLS and nine have no WHERE clause at all, so a set-returning resolver would silently merge workspaces on 12 pages with HTTP 200s → one active workspace, header-preferred, membership-validated. A SET is correct in exactly two places: the workspace switcher and the member roster.
- Two implementations of one scoping rule (RLS in SQL, engine in Python with the service role) → drift is a cross-workspace read → `auth.py` mirrors `current_workspace_id()` exactly and `test_engine_and_rls_agree_on_the_same_header` pins it. Change one, change the other.
- RLS recursion on a membership table → the roster policy calls a function that reads that same table → keep the bootstrap policy a bare `user_id = auth.uid()` comparison, rely on `security definer`, and NEVER `force row level security` on it. A 42P17 surfaces as a 500, so the test asserting a 200 IS the guarantee.
- A keyset cursor on a non-unique column → a bulk insert gives every row the same transaction timestamp, so `created_at < cursor` skips the entire remainder and pagination silently stops early → cursor on the full `(created_at, id)` sort tuple.
- A Postgres timestamptz in a query string → renders as `+00:00`, and an unencoded `+` is read as a SPACE (httpx does not escape it) → emit cursors with a `Z` suffix.
- Adding a column that only ONE code path writes → every pre-existing row renders as the fallback, which is usually the exact bug the column was added to fix (`profiles.email` → truncated UUIDs in the roster) → backfill in the same migration.
- An endpoint that requires a workspace but is the endpoint that GRANTS one → invitation accept deadlocked: the invitee has no membership, so the dependency 403'd them out of the flow that would give them one → `get_identified_user` (authenticated, unscoped) for pre-workspace actions only.
- Live-Supabase test suites that sign in per assertion → GoTrue rate-limits password grants and 429s fail RANDOM tests, which reads as a product defect → cache tokens per user, back off on 429, and invalidate the cache wherever a fixture recreates the same email.
- `pydantic.EmailStr` rejects reserved TLDs (`.test`) → it would refuse this project's own seeded users and every staging address → shape-check instead; the real control is matching the invitation address against the verified JWT email.

## Containerising / deploying

- `Path(__file__).parents[N]` to find a repo-root file → in a container the app sits at `/app/app`, which has fewer parents, so it raises `IndexError` **at import time** and the platform reports only "container failed to listen on PORT" → guard the index and treat the dotenv load as optional. A dev convenience must never be able to take down production.
- `new URL(..., import.meta.url).pathname` for a filesystem path → percent-encodes, so a repo path containing a space becomes `…/07%20Tech%20Projects/…`. Next.js then cannot resolve `outputFileTracingRoot` and **silently skips standalone output while still reporting a successful build** → use `fileURLToPath`, and verify `.next/standalone/**/server.js` exists rather than trusting the build's exit code.
- `NEXT_PUBLIC_*` supplied only at runtime → they are inlined into the client bundle at BUILD time, so a runtime-only value ships as empty and client-side auth silently fails → pass them as Docker build args too.
- Next standalone output does not include `public/` or `.next/static` → they must be copied alongside it or every asset 404s and the page renders unstyled.
- Deleting a workspace whose audit rows exist → blocked by the append-only trigger (`audit_events is append-only (E-AC1)`), which is the guarantee working correctly even against a service-role cascade → isolation-test teardown cannot fully clean up, so orphaned test workspaces accumulate. They are invisible to real users via RLS; do not disable the trigger to tidy them.
